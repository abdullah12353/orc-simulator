Humiliation history (newest first)

    A · Per-portrait anchors

    Each face keeps its own shape. Every portrait ships with an anchor JSON, and each overlay is moved and scaled to it (eye spacing, crown width, jaw width, mouth line).

    B · One template face box

    Every portrait is drawn so its crown, eye line, eye spacing, cheek width and mouth line sit on one shared box. The overlays are drawn once at fixed spots. Identity has to live outside the box: the jaw, chin, ears, gear and colour.

    3 · File format and size (free-tier PWA)

    • Base portraits: lossy WebP, 512×640 (2× a 256×320 card), est. 30–60 KB each → 30 × ~50 KB ≈ 1.5 MB. A 128×160 thumbnail too, est. 5–8 KB each ≈ 0.2 MB. Tusk layers are small transparent WebPs, est. 2–4 KB each.
    • Overlays: 8 transparent lossy WebPs at template size, est. 10–25 KB each ≈ 0.15 MB. Total art ≈ 2 MB, all precached by the service worker. These sizes are my estimates; measure them on the first real portrait.
    • Compose at runtime from stacked absolutely-positioned <img>s (or one SVG with <image>s), with CSS transforms for strategy A. The shareable card uses canvas drawImage in the same order. Never pre-bake combinations: 30 faces × every ≤3-subset of 8 overlays is thousands of files.
    • If the portraits end up as hand-drawn vector like this page, SVG is smaller still (est. 3–10 KB each), and the overlays can be inline SVG <g>s like the ones here.
    • CHECKED Cloudflare Pages Free allows 20,000 files per site and 25 MiB per asset (Pages limits, read 2026-10-29). Static asset requests are free and unlimited (repo research for #2, citing Cloudflare's docs). ~100 small files is nowhere near any limit.
    • CHECKED WebP works in all current Chrome, Edge, Firefox, Opera and Safari, but needs Safari 14+ on macOS 11+ (MDN image types). Lossy WebP supports transparency and is typically ~3× smaller than PNG (Google WebP). AVIF is listed from Safari 16.1 and is ~50% smaller than JPEG (MDN). That could suit us, since iOS push already needs 16.4+, but WebP is the safer default.
    • UNVERIFIED How much an iOS home-screen PWA may cache before eviction. 2 MB is probably fine, but it isn't checked.

    5 · Recommendation

    B + sparse overrides. The template face box is the art brief and the default. A portrait carries an override only where its silhouette leaves the box (in practice the jaw width and the hook's shoulder). Faces are mostly hidden (§1.5), so the identity should live in the jaw, ears, chin and baked gear, which B leaves free. One overlay set fits all 30 with no tuning.
    Plus: layer by slot; pin the muffle and the active disguise so the voice and name always match the face; make removals (lost tusk) base-art flags outside the cap; and keep the Legendary stamp as a frame, outside the cap.
    Fall back to A if the portraits come from raw AI output that nobody will align by hand.
